# Verification feature index

- After transport, registry, strict input, denied control or static app-resource changes, load [foundation](foundation.md): P01 HTTP lanes, restart checks and unresolved host/confirmation gates.
- After release validation/publication, lookup, checklist, source-freshness or generated-guidance changes, load [knowledge](knowledge.md): ten P02 scenarios, immutable pins and local performance measurements.
- After evidence, exact-set compatibility, discount arithmetic or HuntView changes, load [hunt](hunt.md): ten P03 compiled lanes and bounded performance with separate model-agent, host and runner gates.
- After shared MCP adapter or driver changes, run all affected branches.

Live shopping and checkout remain outside the implemented surface. The P07 live card has local bridge/browser evidence; real-host support requires separate session evidence.

P04: [durable hunts](durable.md) owns PostgreSQL state, receipts, incarnation tombstones and lifecycle races.

P05: [authentication](auth.md) owns OAuth, browser linking, authenticated HTTPS MCP and read grants.

P06: [memory and erasure](memory.md) owns durable profile/saved items, exact session-bound browser approval, explicit enrollment, OAuth ownership inventory, atomic deletion and bounded retention.

P07 browser unit: [browser controls](controls.md) owns signed intent links, fresh same-account login, native Stop/Skip confirmation and atomic compact receipts. P07 card unit: [live card](card.md) owns the bundled React card, ext-apps bridge, private grants, monotonic snapshots and polling lifecycle. Full P07 external acceptance remains pending.

P08: [price watches](watches.md) owns browser-confirmed public price watches, verified recipients, the named Pi Hut parser and bounded public fetch, pg-boss wakes, the fenced durable outbox, unsubscribe, cancellation and erasure.

P09 S1: [lineage](lineage.md) owns database lineage identity, admission, the shared fenced transaction opener, seal/unseal fences and runtime refusal of restored or unadmitted databases. P09 S2: [recovery](recovery.md) owns the recovery CLI, the sealed two-database handoff (restore, source consumption, target bind) and atomic target migration. P09 perf: [story performance](story-performance.md) owns the `perf -- p09` end-to-end hunt and watch-notification metric and its guard. P09 S3: [operations](operations.md) owns the shared release artifact digest, truthful health and schema readiness, the database pool owner, `SCOAT_LISTEN_HOST`, systemd units, hosted CI coverage and `perf -- p09`.

P09 S4: [acceptance](acceptance.md) owns the one linked public story across P03 to P09 surfaces, its synthetic-condition boundary, review media and evidence scans. Phase branches stay regressions; the story does not replace them.
