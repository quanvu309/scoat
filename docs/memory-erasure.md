# Durable Memory and erasure

P06 is a runnable local draft. `scoat_memory` reads the declared profile, counts, bounded saved/recent lists and individual immutable saved results. Lists use account-scoped cursors and at most 20 rows. Recent hunts order by start time and ID. Saving retains the exact finished HuntView including text, pinned release, profile and price evidence, with a format version and digest. An unfinished hunt produces no saved item. Later profile or release changes do not rewrite a saved result. Starting with a null profile reads the declared profile and its revision in the same fenced creation transaction; explicit profiles record explicit provenance.

Profile and save accept a request key and strict payload. The first call persists a five-minute proposal and returns a browser URL. Open it, freshly authenticate the same account, inspect the exact command, and explicitly approve. Approval is one-use and browser bound. Resubmit the identical tool command from the original client and live OAuth session. Application and compact receipt commit together. Reusing a key with changed bytes, another session/client, expired approval or inactive account fails. Identical retries replay the compact outcome for one hour; the key remains reserved until account erasure. No caller-supplied Person value grants this authority.

Open `/account/erase`, freshly authenticate and explicitly confirm the destructive form. Before submission, retain the random status capability displayed by the page. The coordinator locks sorted subject identities, acquires the exclusive account fence and rechecks the identity inventory, then invokes authentication, Memory and Hunts deletion ports, checks for survivors and commits the incarnation tombstone with a precise category receipt. It deletes profiles, saved snapshots, proposals/command receipts, hunt rows/offers/compatibility/receipts, identities, read grants, all normalized owned OAuth artifacts and account-bound browser flows. OAuth ownership includes every nested accountId, multiple owners and inherited Grant/Session owners. Writes and reads acquire active account fences; deletion also removes an artifact shared with an erased owner. Late artifacts, old bearers and cached principals fail closed. There is no queue, watch, reservation or email state in this phase; job count is explicitly zero.

The completion POST response contains category counts and retention limits. A lost response can be recovered by POSTing `status` to `/account/erase-status` from the configured origin. Only its SHA-256 hash, random operation, completion time and policy are retained for 24 hours after completion; pending capabilities expire in five minutes. Status does not retain the private command or count receipt. Account/incarnation tombstones and HMAC subject suppression records expire after 31 days. Suppression stores no raw subject and rejects enrollment flows initiated before erasure. Unknown identity login never provisions silently: a fresh authenticated browser must explicitly enroll a new random account/incarnation. Previously mapped identities are removed, not silently linked into a new account.

Persist `lifecycleKey` and `lifecycleKeyVersion` in the private issuer configuration alongside existing cookie/signing keys. Startup refuses missing keys. Disposable fixtures generate test-only keys. Rotation requires an audited ledger migration; changing the key without migrating existing suppression digests invalidates old callback protection. No production secret is generated automatically.

Apply `npm run db:migrate` before service launch. Migration 0002 adds Memory, ownership inventory, retention and provenance. It revokes pre-inventory OAuth artifacts and browser flows once, forcing sign-in, rather than guessing old parent ownership. A version marker makes repeated application safe. The production startup installation runs under the same database advisory lock. Bounded maintenance runs at startup and through `DATABASE_URL=… npm run accounts:maintain`; each category processes at most 100 rows per invocation, with a maximum internal limit of 1000. Expired proposal payloads are cleared while reserving keys. Deployment must schedule repeated maintenance to drain a backlog; no scheduler has been deployed.

Normal service logs contain fixed refusal event names, not payloads or credentials. Upstream identity provider records, host transcripts/exports and already delivered or provider-accepted mail cannot be recalled by local erasure. Backups must expire within 30 days, and suppression ledger changes must replicate before restores are admitted to traffic. Backup expiry, replication, restore reconciliation, key custody and periodic maintenance scheduling are operational gates, currently UNTESTED. Restoring a backup without the current suppression ledger can resurrect private records and must not serve traffic.

Run `npm run build`, `npm run typecheck`, `npm run lint`, `npm test`, `npm run verify -- p04`, `npm run verify -- p05`, `npm run verify -- p06` and `npm run perf -- p06`. Drivers use compiled modules, real local PostgreSQL and HTTPS with disposable identities. Evidence includes migration, killed-connection rollback/restart, actual 55P03 account contention, late-write denial, nested ownership negative proof and raw performance samples. Local synthetic browser transcripts do not satisfy real-host, external-provider, model-agent, screenshot/video or fixed two-vCPU gates. The absent queue and absent trunk runtime baseline remain declared measurement limits. P03 shared-host performance remains inconclusive: 1056 ms failure and 947 ms isolated pass at the same earlier head; causality is unproven.
